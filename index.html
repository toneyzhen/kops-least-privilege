Least Privilege Simulator

The principle of least privilege means giving every person and every program only the access it needs to do its job, and nothing more. Picture an office building with key cards. The cleaner's card opens the supply closet, not the server room. If someone steals that card, they can't get far.

We'll use a Kubernetes cluster on AWS, built with a tool called kOps. Below you can flip between two worlds and see what changes.

What are these? (AWS, Kubernetes, kOps)
AWS
Amazon's cloud. You rent computers and storage from it.
Kubernetes
Software that runs and manages many small apps across many computers.
kOps
A tool that builds a Kubernetes "cluster" (a group of computers working together) on AWS for you.

More words are explained in the glossary at the bottom.

    Step 4

    The 5 rules this project follows

    1. Give each person and program its own identity

      Nobody shares a key card. Admins, developers, and apps each log in as themselves, so you can see who did what.

      Show the technical details
      authentication:
  aws:
    backendMode: CRD
    clusterID: ${CLUSTER_NAME}
# humans sign in with an AWS role; the session name
# shows up in logs as developer:<who>

    2. Grant only what the job needs

      The developer can manage apps in their own team's area. The app can read one folder. That's it.

      Show the technical details
      {
  "Sid": "ReadAllowedPrefixObjects",
  "Effect": "Allow",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::${DEMO_DATA_BUCKET}/allowed/*"
}

    3. Block the riskiest actions outright

      Some things, like creating new AWS users or weakening the settings bucket, are refused even for admins. A "Deny" always wins.

      Show the technical details
      {
  "Sid": "DenyWeakeningStateStoreBucket",
  "Effect": "Deny",
  "Action": ["s3:PutBucketPolicy", "s3:DeleteBucket", "..."],
  "Resource": "arn:aws:s3:::${KOPS_STATE_BUCKET}"
}

    4. Make admin access short-lived

      Admin access needs a second proof of identity (a code from your phone) and expires after one hour. There is no permanent admin password to steal.

      Show the technical details
      {
  "Effect": "Allow",
  "Principal": {"AWS": "arn:aws:iam::${AWS_ACCOUNT_ID}:root"},
  "Action": "sts:AssumeRole",
  "Condition": {"Bool": {"aws:MultiFactorAuthPresent": "true"}}
}
# role created with --max-session-duration 3600 (1 hour)

    5. Assume something will get broken into, and limit how far it spreads

      Apps can't see the server's keys, can't talk to each other by default, and can't gain admin rights. A break-in stays small.

      Show the technical details
      apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: team-a
spec:
  podSelector: {}
  policyTypes: ["Ingress", "Egress"]
    Reference

    Glossary

    AWS
    Amazon's cloud, where you rent computers, storage, and more.
    IAM
    AWS's key-card system: it decides who may do what in an AWS account.
    Kubernetes
    Software that runs many small apps across a group of computers and keeps them healthy.
    kOps
    A tool that builds and maintains a Kubernetes cluster on AWS.
    Pod
    One running copy of an app inside the cluster.
    S3 bucket
    A folder in the cloud for storing files.
    Instance metadata (IMDS)
    A special address a server can ask for its own AWS keys. If an attacker reaches it, they can borrow the server's identity.
    RBAC
    Kubernetes's key-card rules: which person or app may do which action on which thing inside the cluster.
    IRSA
    A way to give one app its own small AWS key card, instead of sharing the whole server's.
    Secret
    Kubernetes's safe for passwords and tokens.
